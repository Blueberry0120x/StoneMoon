Stone Moons is a hypertext novel by Deena Larsen, originally created in Storyspace on a 1997 Macintosh with 491 nodes and 6,000 multi-destination links. It was declared dead at CyberMountain in 1999 when it overran its buffers. From 2023–2025, a team of WSUV Digital Technology & Culture students resurrected it into Twine Harlowe 3.3.5 — 533 passages, 192,382 words. Jenn Duyen Nguyen led all CSS and visual design work.

CONTEXT

The Challenge

When Stone Moons was resurrected from the 1997 Macintosh, the team faced a question that had nothing to do with code: What should this work look like? StorySpace had a very specific visual language. Nodes appeared as labeled rectangular boxes on a spatial canvas. Readers navigated by clicking named links — a popup would list every possible destination — and the structure of the story was visible. You could see the shape of the world.

Twine doesn't work that way. Twine presents one passage at a time in a reader's browser. The spatial map — the wine-glass topology Deena designed — would be invisible to readers unless someone built it back. That was Jenn's assignment.

CONTRIBUTIONS

What Jenn Built

01 The Map — Recreating the Storyspace Canvas

Jenn designed and hand-coded a CSS spatial map that recreates the visual environment of StorySpace's original 1999 node canvas. Every passage in Stone Moons is represented as a box on this map — styled to mirror the look and proportions of a StorySpace lexia node: a rectangular card with a title bar, a horizontal divider line, and the node label rendered in compact ellipsized text, exactly as it appeared on Deena's 1997 Macintosh.

She placed all 533 passages by hand using absolute CSS coordinates — Sarah's 249 nodes arranged along the rim and outside of the glass, Laurel's 53 passages clustered at the base in four concentric spiral layers, The Moon's passages filling the interior. The resulting map is a 2D scrollable canvas where readers can see the full wine-glass shape of the novel before they read a single word.

To keep the three narrative voices distinct at a glance, Jenn built a full color-coded system:

Sarah — blue, the color of correspondence, struggle, the outside world
Laurel (yellow) — facilitated voice, pre-verbal thought
Laurel (green) — second mode of Laurel's inner world
The Moon — black, the mythic, the unseen, the predatory deity

This color system runs through every border, shadow, header, and link chip — creating a visual grammar readers learn intuitively as they move through the piece.

02 The Popup — Replicating Named Links

One of Stone Moons' defining features is its named links — Deena used the names of the links themselves as part of the story. In StorySpace, clicking an anchor word brought up a dialog box listing every possible destination by name, each name carrying its own joke, irony, or subtext. Replicating that behavior in a modern browser, without JavaScript, was one of Jenn's key design problems.

She solved it with a pure-CSS popup system. Hovering over any multi-destination link in Stone Moons causes a styled tooltip to appear — built entirely with CSS using the .og-link, .popup, and ::before triangle arrow pattern. The popup fades in smoothly with a transition: opacity 0.5s ease, floats above the text with absolute positioning, and is styled to feel like a StorySpace dialog.

This was her first original contribution — visible in the earliest archived CSS build from January 23, 2025.

03 Navigation Image Library

Stone Moons uses images for navigation — not text links alone. The reader's choices are presented as visual navigation elements: Continue / Delve Deeper, Higher / Lower, Go Back / Press On, Moon / Sarah, and more. Jenn designed and integrated a library of 30+ navigation image components — each class specifying the exact aspect ratio, flexbox layout, and pixel-precise dimensions to render the navigation mosaics cleanly at every screen size.

Each image is embedded directly in the Twine HTML as a base64 asset — no external dependencies, no CDN, no broken links after 30 years. The work is fully self-contained because of how Jenn structured the CSS image system.

She then built 8+ responsive breakpoints calibrated to specific screen width ranges — from 700px to 3100px — so that paired navigation images remain pixel-aligned regardless of the reader's screen size or resolution.

04 Twine Override Layer

Twine's Harlowe engine ships with a dark default theme. Stone Moons needed the opposite: the white-and-gray aesthetic of StorySpace's reading pane. Jenn wrote a comprehensive override layer targeting Harlowe's native elements — restyling the entire reading experience from the ground up:

  • Passage boxes: gray border, subtle box-shadow, minimum width of 824px — the constrained reading window of StorySpace
  • Links: red, always — matching StorySpace's classic hyperlink color from 1999
  • The map passage itself: no border, no padding, no shadow — a clean canvas behind the node layout
  • Sidebar z-index management so the map overlay renders above Twine's default chrome

This override layer is what makes Stone Moons feel like it was born in 1999, even though it runs in a 2025 browser.

05 Design Token System & Responsive Architecture

Jenn built the entire CSS system using design tokens — CSS custom properties defined at :root. Colors, sizes, and character palettes are defined once and referenced everywhere. This means the visual design can be updated in one place and cascade across all 533 passages.

She also architected dark mode support in the token structure, with commented-out dark variants ready for future implementation.

Bookend — Closing Statement

Jenn's work on Stone Moons is a rare kind of technical contribution: it is simultaneously archaeological and architectural. She studied what StorySpace looked like — its node boxes, its named-link dialogs, its spatial canvas — and then rebuilt that environment in a technology it was never designed for, from the ground up, in pure CSS.

The result is that readers who open Stone Moons in 2025 see the work as Deena envisioned it in 1999 — the wine-glass shape of the narrative visible, the three voices color-coded and distinct, the named links hovering in their original dialog-style popups, the navigation images rendered at pixel-perfect precision on every screen.

Stone Moons was declared dead at CyberMountain in 1999. Jenn's design work is part of what brought it back — not just functional, but visually alive.

— Transitions to: Closing Remarks, Deena Larsen
